## Сутності:

- User - зареєстрований користувач платформи. Може виступати в ролі глядача (переглядати стріми, писати в чат, оформлювати підписки) або в ролі стрімера (створювати та вести власні трансляції). Користувач може мати лише одну активну сесію (пристрій) та проводити не більше одного стріму одночасно;
- Stream - активна пряма трансляція що має відповідні елементи: відео, чат, кнопка оформлення підписки та додання в улюблене канал користувача що веде стрім;
- Chat - елемент стріма що має поле з введенням повідомлення та історією повідовлень;
- Video - картинка прямої трансляції
- Subscription - підписка що може бути оформленна кожен місяць і кошти за оформлення якої частково йдуть на рахунок каналу
- Message - повідомлення надіслане користувачем в чат стріма

## Атрибути

User:

- user_id | int | PK
- tel | varchar(20)
- email | varchar(255)
- name | varchar(100)
- payment_methods | varchar(50)
- age | int

Stream:

- user_id | int | FK
- stream_id | int | PK
- status | varchar(50)
- video_id | int | FK
- chat_id | int | FK

Chat:

- chat_id | int | PK
- stream_id | int | FK
- message_list | text (або array)

Message:

- chat_id | int | FK
- message_id | int | PK
- user_id | int | FK
- text | text
- sent_at | timestamp

Video:

- video_id | int | PK
- stream_id | int | FK
- duration | time

Subscription:

- subscription_id | int | PK
- price | decimal(10,2)
- time (trial) | int
- subscriber_id | int | FK
- streamer_id | int | FK
- commission | decimal(5,2)

## Зв'язки між сутностями

user -> subscription - 1:N один користувач як subscriber може оформити безліч підписок, але кожна підписка може належати лише до 1 subscriber. так само із user в ролі streamer
user -> stream - 1:N один користувач (streamer) може мати безліч стрімів але лише 1 в активному статусі. Cтрім може належати лише до одного стрімера.
stream -> user - N:N один стрім може мати безліч user (viewer), водночас один глядач може переглядати безліч стрімів за раз.
stream -> chat - 1:1 кожен стрім має власний чат, кожен чат належить лише 1 стріму
stream -> video - 1:1 кожен стрім має власне відео, кожне відео належить лише одному стріму
chat -> message - 1:N кожен чат може мати безліч повідомлень, кожне повідомлення належить лише 1 чату
user -> message - 1:N кожен юзер може мати безліч повідомлень, кожне повідомлення належть лише 1 користувачу
