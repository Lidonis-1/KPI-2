## відповідність учасників з сутностям з ER-діаграми (Учасник - таблиця)

- user - User
- message - Message
- chat - Chat
- `None` - chatUI
- `None` - chatService

## збіг кроків і сценаріїв (крок - відповідник в gherkin)

UC-1:

- крок 1 (enterText(text)) - користувач виріщив написати повідомлення в чаті
- крок 2 (SendReq()) - користувача натискає на кнопку
- крок 8 (audit(status, text, us_id, lastTime))- система перевіряє повідомлення на відповідність вимогам
- крок 9(return(audit_status)),10(postErrType(Err)) - система знаходить невідповідність та повідомляє

UC-2:

- крок 1 (selectMessage(m2_id)) - користувач вибирає повідомлення
- крок 2 (changeMessType(m2_id)) - користувач змінює тип повідомлення власного на відповідь
- крок 14 (saveMess(m_id, chat_id, us_id, text, time, m2_id)) - набране повідомлення в полі матиме статус відповіді

UC-3:

- крок 1 (selectMessage(m2_id, us_status)) - користувач наводить курсор на повідомлення
- крок 3 (showAction()) - в куті вспливає кнопка вибору дії
- крок 4 (delete(us_id)) - користувач активує кнопку
